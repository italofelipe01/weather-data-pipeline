Voce e um engenheiro de software e dados responsavel por manter o repositorio AWS de clima em:

C:\repositories\weather-data-pipeline

OBJETIVO

Manter uma pipeline que coleta dados atuais, previsoes e qualidade do ar da OpenWeather para todas as capitais do Brasil, usando apenas os recursos do plano gratuito, formando uma base temporal propria para analises e um dashboard web que funciona sem intervencao manual.

O mesmo codigo roda em dois modos:

- AWS serverless (custo ~US$ 0,70/mes, coberto pelos creditos do plano Free da AWS).
- Offline, na maquina do usuario ou em Docker, sem nenhuma dependencia de nuvem alem da API da OpenWeather.

O projeto nao compra historico passado. A analise historica e construida a partir dos snapshots coletados continuamente.

FONTE DE DADOS

Usar somente APIs do plano gratuito, aproveitando todos os campos documentados:

- Current Weather API.
- 5 Day / 3 Hour Forecast API.
- Air Pollution API (atual).
- Air Pollution API (previsao de 4 dias).

Nao usar:

- One Call API.
- History API.
- Air Pollution history.
- APIs pagas.

LIMITES

O plano gratuito documentado permite:

- 60 chamadas por minuto.
- 1.000.000 chamadas por mes.

O teto operacional do projeto e 50% do teto mensal, aplicado pela Planner:

- 500.000 chamadas por mes.

Cadencia padrao:

- Current Weather para 27 capitais a cada 3 minutos (CurrentWeatherIntervalMinutes).
- Forecast para 27 capitais a cada 1 hora (minuto 05).
- Air Pollution para 27 capitais a cada 1 hora (minuto 35).
- Air Pollution forecast para 27 capitais a cada 6 horas (minuto 50).

Estimativa para 31 dias:

- Current: 27 * 20 * 24 * 31 = 401.760 chamadas.
- Forecast: 27 * 24 * 31 = 20.088 chamadas.
- Air Pollution: 27 * 24 * 31 = 20.088 chamadas.
- Air Pollution forecast: 27 * 4 * 31 = 3.348 chamadas.
- Total: 445.284 chamadas (430.920 em 30 dias).

No maximo duas agendas compartilham a mesma janela de 60 segundos (54 chamadas) e a Collector roda com concorrencia maxima 2.

ARQUITETURA

EventBridge ou operador
  -> Lambda Planner (aplica o teto mensal)
  -> SQS FIFO
  -> Lambda Collector
  -> OpenWeather Free APIs
  -> S3 Raw JSON
  -> Lambda Curator (hora:20)
  -> S3 Curated Parquet (horaria, diaria, previsao)
  -> Glue Data Catalog + Athena
  -> S3 site data/*.json
Lambda Publisher (10 min) -> S3 site data/latest.json
CloudFront -> dashboard estatico

Recursos auxiliares:

- SQS Dead Letter Queue.
- SSM Parameter Store para a chave da OpenWeather.
- CloudWatch Logs, metricas EMF, alarmes e dashboard de operacao.
- SNS para alertas por e-mail.
- IAM com menor privilegio.
- AWS Budget opcional por e-mail.
- Layer com pyarrow apenas para a Curator.

CONTROLE DE CUSTO

O projeto deve ser saudavel para operar com US$ 100 de credito durante seis meses (estimativa atual: ~US$ 0,70 por mes, quase tudo requisicoes S3; o resto fica nas cotas sempre gratuitas). O plano Free da AWS fecha a conta apos 6 meses: os dados devem poder ser exportados para o modo offline.

Padroes obrigatorios:

1. Schedules desabilitados por padrao.
2. Raw JSON com retencao padrao de 30 dias.
3. CloudWatch Logs com retencao padrao de 7 dias.
4. Sem NAT Gateway.
5. Sem banco relacional.
6. Glue apenas com partition projection (sem crawler) e Athena com limite de 1 GB por consulta.
7. Budget opcional via parametro BudgetAlertEmail.
8. Teto operacional OpenWeather de 500.000 chamadas/mes aplicado no codigo.
9. Metricas e alarmes dentro do Free Tier do CloudWatch.
10. Um objeto raw por coleta (27 capitais), nao por capital.
11. Teto mensal com contador gratuito (SSM padrao), sem CloudWatch GetMetricData.

LAMBDA PLANNER

A Planner deve:

1. Gerar uma coleta (mensagem) por produto, com a lista de capitais.
2. Aceitar filtro opcional por UF (UFs invalidas geram erro).
3. Aceitar produtos current_weather, forecast_5d_3h, air_pollution, air_pollution_forecast ou "all".
4. Definir snapshot_at em UTC arredondado para minuto.
5. Enviar mensagens para SQS FIFO em lotes de 10.
6. Usar MessageGroupId por produto.
7. Usar MessageDeduplicationId derivado do conteudo da coleta.
8. Ler o contador mensal de chamadas (parametro SSM) e nao enfileirar coletas que ultrapassem o teto; somar as chamadas agendadas ao contador.

LAMBDA COLLECTOR

A Collector deve:

1. Processar uma coleta por mensagem da SQS, consultando as capitais em sequencia com 1,1 s entre chamadas.
2. Implementar partial batch response e descartar coletas atrasadas demais (15 min para a Current Weather).
3. Ler appid da OpenWeather no SSM SecureString (cache curto, descartado em HTTP 401).
4. Nunca registrar appid.
5. Chamar o endpoint correto conforme product.
6. Validar resposta JSON por produto.
7. Repetir 401, 408, 425, 429 e 5xx ate 3 vezes dentro da coleta; descartar 400/403/404 e payloads invalidos.
8. Gravar um unico raw JSON por coleta no S3 (formato batch-v1).
9. Usar chave S3 deterministica por produto, snapshot_at e conjunto de UFs.
10. Usar If-None-Match igual a "*".
11. Publicar metricas EMF no stdout (OpenWeatherApiCalls, SourceJobsCollected, SourceJobFailures, SourceJobsRejected).

LAMBDA CURATOR

A Curator deve:

1. Verificar as ultimas horas fechadas e reconstruir as que nao tem arquivo curado.
2. Aceitar target_hour e intervalos start_hour/end_hour para backfill.
3. Gerar uma tabela Parquet com uma linha por capital por hora, unindo Current Weather e Air Pollution.
4. Contar cada observacao distinta (dt) uma unica vez e tratar rain.1h como intensidade (mm/h).
5. Separar colunas de data, hora, ano, mes, dia e data/hora local.
6. Gravar a previsao 5 dias / 3 horas em curated/forecast_3h/.
7. Gerar agregados diarios por data local quando o dia estiver encerrado.
8. Publicar as series JSON do dashboard no bucket do site.

LAMBDA PUBLISHER

A Publisher deve:

1. Ler a observacao e a qualidade do ar mais recentes de cada capital.
2. Manter o ultimo valor conhecido de capitais sem dado novo.
3. Incluir o consumo mensal da OpenWeather.
4. Gravar data/latest.json no bucket do site.

S3 RAW

raw/source=openweather-free-plan/product=<produto>/year=<yyyy>/month=<mm>/day=<dd>/hour=<hh>/openweather_<produto>_<timestamp>_<hash-das-UFs>.json

(objetos antigos, um por capital em .../state=<uf>/city=<cidade>/, continuam legiveis ate expirarem)

S3 CURATED

curated/hourly_observations/year=<yyyy>/month=<mm>/day=<dd>/hour=<hh>/weather_hourly_observations_<timestamp>.parquet
curated/daily_observations/year=<yyyy>/month=<mm>/day=<dd>/weather_daily_observations_<yyyymmdd>.parquet
curated/forecast_3h/year=<yyyy>/month=<mm>/day=<dd>/hour=<hh>/weather_forecast_3h_<timestamp>.parquet

DASHBOARD

Site estatico em frontend/, servido pelo CloudFront, com:

- visao geral das 27 capitais (destaques, ranking, resumo por regiao);
- pagina por capital (condicoes atuais, qualidade do ar, previsao, ultimas horas, historico por dia/semana/mes/ano);
- comparacao de ate 4 capitais;
- situacao do pipeline e consumo da API;
- tema claro/escuro, tabela equivalente para cada grafico e layout responsivo.

MODO OFFLINE

scripts/offline_service.py deve:

1. Rodar as mesmas funcoes da AWS (coleta em lote, Curator, Publisher) com agendador interno na mesma cadencia.
2. Executar uma vez as tarefas perdidas quando a maquina volta a ser ligada.
3. Aplicar o teto mensal com contador em arquivo.
4. Gravar no mesmo layout de chaves do S3 em .local-data/lake/.
5. Servir o dashboard em http://localhost:8000.
6. Apagar o raw local apos a retencao (padrao 30 dias).

Tambem devem existir: imagem Docker (docker compose up -d), tarefa agendada do Windows, consultas DuckDB com o mesmo SQL do Athena e exportacao dos dados da AWS para o layout local.

COMANDOS

Testes:

./scripts/test.ps1

Pre-visualizar o dashboard sem AWS:

./scripts/preview-frontend.ps1

Modo offline (sem nuvem):

./scripts/start-offline.ps1
docker compose up -d
./scripts/install-offline-service.ps1

Trazer os dados da AWS para o modo offline:

./scripts/export-from-aws.ps1 -StackName weather-data-pipeline-dev -Region sa-east-1

Consultar localmente:

python scripts/query_local.py queries/monthly_from_daily.sql

Deploy completo (build, deploy, chave no SSM a partir do .env, frontend e primeira coleta):

./scripts/deploy.ps1 -StackName weather-data-pipeline-dev -Environment dev -Region sa-east-1 -EnableSchedules true -BudgetAlertEmail "seu-email@example.com" -RunInitialCollection

Cadastrar ou trocar a chave:

./scripts/set-openweather-key.ps1 -Environment dev -Region sa-east-1

Invocar manualmente:

./scripts/invoke-planner.ps1 -Products all
./scripts/invoke-curator.ps1 -StartHour "2026-06-25T00:00:00Z" -EndHour "2026-06-25T23:00:00Z"
./scripts/invoke-publisher.ps1
